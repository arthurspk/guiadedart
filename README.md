## :dart: O guia para alavancar a sua carreira

> Dart é a linguagem criada pelo Google para construir aplicações rápidas em qualquer plataforma — é a linguagem por trás do Flutter, hoje um dos frameworks mais usados para apps mobile, web e desktop no Brasil e no mundo. Null safety por padrão, compilação nativa (AOT) para produção e modo de desenvolvimento com hot reload, além de recursos modernos como records, patterns e class modifiers (Dart 3), fazem dela uma linguagem produtiva tanto em projetos pequenos quanto em apps em produção com milhões de usuários. Este guia foca na **linguagem Dart em si** — sintaxe, tipos, assincronismo, ferramentas de linha de comando e o ecossistema de pacotes — e não é um guia de Flutter (esse tem [seu próprio guia na rede Guia Dev Brasil](https://github.com/arthurspk/guiadeflutter)). Os recursos aqui servem tanto para quem usa Dart via Flutter quanto para quem escreve back-ends, CLIs e scripts em Dart puro.

## 💡 Nossa proposta

> A proposta deste guia é dar uma ideia sobre o atual panorama e guiá-lo se você estiver confuso sobre qual será o seu próximo aprendizado, sem influenciar você a seguir os 'hypes' e 'trends' do momento. Acreditamos que com um maior conhecimento das diferentes estruturas e soluções disponíveis poderá escolher a ferramenta que melhor se aplica às suas demandas. E lembre-se, 'hypes' e 'trends' nem sempre são as melhores opções.

## 🛠️ Ferramentas

> Executar, compilar e empacotar

- [DartPad](https://dartpad.dev) — Editor online oficial: escreva e rode Dart no navegador sem instalar nada.
- [pub.dev](https://pub.dev) — Repositório oficial de pacotes Dart e Flutter.
- [dart format](https://dart.dev/tools/dart-format) — Formatador de código oficial, sem configuração.
- [dart fix](https://dart.dev/tools/dart-fix) — Aplica automaticamente correções sugeridas pelo analisador.
- [dart compile](https://dart.dev/tools/dart-compile) — Compile seu código Dart para executável nativo, JS ou snapshot.
- [pub (gerenciador de pacotes)](https://dart.dev/tools/pub/cmd) — Comandos oficiais para instalar, atualizar e publicar pacotes.
- [Dart DevTools](https://dart.dev/tools/dart-devtools) — Suíte de depuração e performance: inspetor, profiler de CPU/memória e mais.

> Frameworks e CLIs para back-end em Dart

- [Dart Frog](https://dartfrog.vgv.dev) — Framework minimalista para construir back-ends e APIs em Dart puro, da Very Good Ventures.
- [Shelf](https://pub.dev/packages/shelf) — Micro-framework oficial do time Dart para servidores web, usado como base por vários outros frameworks.
- [Serverpod](https://docs.serverpod.dev) — Framework de back-end full-stack em Dart, com ORM, autenticação e geração de cliente.
- [Vaden](https://pub.dev/packages/vaden) — Framework de back-end em Dart inspirado no Spring Boot, construído pela comunidade Flutterando.
- [dcli](https://pub.dev/packages/dcli) — Biblioteca para escrever scripts de linha de comando em Dart no estilo shell script.
- [very_good_cli](https://pub.dev/packages/very_good_cli) — CLI para criar projetos Dart/Flutter com testes, CI e estrutura prontos.
- [Melos](https://melos.invertase.dev) — Ferramenta para gerenciar monorepos com múltiplos pacotes Dart.

- [Dart Code Metrics (DCM)](https://dcm.dev/docs/cli/) — Analisador estático avançado: métricas de complexidade, regras extras e relatórios.

- [package:test](https://pub.dev/packages/test) — Framework oficial de testes unitários e de integração para Dart.
- [package:mocktail](https://pub.dev/packages/mocktail) — Biblioteca para criar mocks em testes, sem geração de código.
- [package:build_runner](https://pub.dev/packages/build_runner) — Executa geradores de código (como freezed e json_serializable) sobre seus arquivos Dart.
- [package:freezed](https://pub.dev/packages/freezed) — Geração de código para classes imutáveis, union types e cópia de objetos.
- [package:json_serializable](https://pub.dev/packages/json_serializable) — Gera código de serialização/desserialização de JSON automaticamente.
- [package:args](https://pub.dev/packages/args) — Parser oficial de argumentos de linha de comando.
- [package:collection](https://pub.dev/packages/collection) — Utilitários extras para trabalhar com listas, sets e maps.
- [package:path](https://pub.dev/packages/path) — Manipulação de caminhos de arquivo de forma multiplataforma.
- [package:intl](https://pub.dev/packages/intl) — Internacionalização: formatação de datas, números e mensagens traduzidas.
- [package:equatable](https://pub.dev/packages/equatable) — Simplifica comparação de igualdade entre objetos, sem escrever == e hashCode na mão.
- [result_dart](https://pub.dev/packages/result_dart) — Implementação do tipo Result (sucesso/erro) para Dart, inspirado em Rust e Kotlin. Feito pela comunidade Flutterando.
- [auto_injector](https://pub.dev/packages/auto_injector) — Container de injeção de dependência simples para Dart, da comunidade Flutterando.
- [package:http](https://pub.dev/packages/http) — Cliente HTTP oficial e mais usado do ecossistema Dart.
- [package:dio](https://pub.dev/packages/dio) — Cliente HTTP com interceptors, cancelamento de requisições e mais recursos.

## 🤖 IA na prática

Dart e assistentes de IA formam uma dupla natural dentro do ecossistema Flutter: o próprio time do Dart mantém pacotes oficiais para conectar agentes de IA ao seu projeto via **MCP (Model Context Protocol)**, além de documentação dedicada a boas práticas de uso.

**Para aprender**
- Peça para um assistente **explicar um trecho de código Dart linha a linha**, incluindo o que muda com null safety, records ou patterns (recursos do Dart 3).
- Cole um erro do analisador (`dart analyze`) e peça para a IA explicar a causa e sugerir uma correção idiomática, sem "silenciar" o erro com `// ignore`.
- Peça **exercícios com gabarito** sobre um tópico específico (generics, isolates, extension methods) para praticar.

**Para trabalhar**
- Configure o [Dart MCP server](https://pub.dev/packages/dart_mcp_server) para dar a assistentes como Claude Code, Cursor ou Gemini acesso direto a comandos como `dart analyze`, `dart test` e `dart format` do seu projeto — veja o guia oficial em [Get started developing with AI](https://docs.flutter.dev/ai/get-started).
- Use [GitHub Copilot](https://github.com/features/copilot), [Cursor](https://cursor.com) ou [Claude Code](https://code.claude.com/docs/en/overview) para gerar boilerplate (classes `freezed`, testes com `package:test`, clientes HTTP) e sempre rode `dart analyze` e `dart test` depois de aceitar qualquer sugestão.
- Para apps que usam IA generativa dentro do próprio produto, veja o [Genkit for Dart](https://genkit.dev/docs/dart/get-started), framework oficial para construir funcionalidades de IA full-stack em Dart e Flutter.

**Limites e boas práticas**
- IA **inventa nomes de pacotes e APIs** do pub.dev, principalmente para versões recentes. Confirme sempre em [pub.dev](https://pub.dev) antes de adicionar uma dependência sugerida.
- Prefira null safety explícito a sugestões que abusam de `!` (bang operator) só para o código compilar — isso reintroduz os bugs que o null safety existe para evitar.
- Não cole código proprietário, chaves de API ou dados de clientes em ferramentas de IA sem verificar a política da sua empresa.
- Entenda o que você aceita: em entrevista e em produção, o código é seu — siga as recomendações de [Flutter AI best practices](https://docs.flutter.dev/ai/best-practices).
